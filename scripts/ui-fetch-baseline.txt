# Raw fetch() sites outside ui/src/api, with why each one is here.
#
# The api client attaches the X-CSRF-Token every mutating route requires; a raw
# fetch does not, so the middleware answers 403 "CSRF token required" and the
# action silently fails. Proved in the real logged-in app (seed#2389):
#
#   raw fetch  PUT /api/v1/settings -> 403 {"error":"CSRF token required"}
#   with token PUT /api/v1/settings -> 200 {"status":"updated"}
#
# A read-only raw fetch still bypasses the client's 401 -> refresh -> retry, so
# an expired token surfaces as an error instead of being refreshed quietly.
#
# This list may only shrink. scripts/check-ui-fetch.py fails on a new site and
# on an entry that no longer matches, so it cannot drift into fiction.
#
# No MUTATING entries remain: every mutating call outside the exempt set now
# goes through the api client (seed#2389). The read-only ones are the
# remaining debt — they bypass the client 401 refresh/retry.
